# e편한세상강동에코포레 온라인 주민의견서 · 온라인 동의서

입주민이 링크 하나로 접속해 문서를 읽고, 답변을 선택한 뒤 동·호수·성명과 직접 서명을 입력해 제출하는 웹페이지입니다.
회원가입·로그인·휴대폰 인증·GPS 수집은 없고, 동·호수·성명·서명만으로 본인인증을 한 것은 아닙니다.
선거나 전자투표 시스템이 아니라, 종이 문서를 온라인으로 접수해 DB에 보관하는 서비스입니다.

주민 주소(`/opinion`)는 하나이며, 관리자가 **공개 중**으로 지정한 **안건** 하나를 보여 줍니다.

- **기존 안건** `EPOXY_OPINION` — 처음 만든 단일 문항 주민의견서(아래 '주민의견서' 절). 기록·화면·CSV·PDF는 그대로 유지됩니다.
- **새 안건** `MANAGER_REQUEST_2026` — 「관리사무소장 교체 및 관리업무 특별조사 요청 온라인 동의서」(아래 '온라인 동의서 안건' 절).
  질문 3개에 각각 동의/비동의, 개인정보 수집·이용 동의, 제출처(케이비아주·강동구)별 제공 동의를 따로 받습니다.

- 주민 페이지: `/` → `/opinion`
- 관리자: `/admin` (비밀번호 로그인)

## 주요 기능

**주민 페이지 (모바일 우선)**
- 의견서 본문 표시 (PDF 원문 그대로, 굵은 글씨 유지)
- 의견 선택: `위 주민의견서 내용에 동의합니다.`(AGREE) / `위 주민의견서 내용에 동의하지 않습니다.`(DISAGREE)
- 동·호수(숫자, 뒤에 `동`/`호` 자동 표시), 성명, 손가락·마우스 직접 서명(Canvas), 기타 의견(선택, 1,000자)
- 본인 의사 확인·제출 및 활용 동의 체크 (둘 다 체크해야 제출 버튼 활성화)
- 제출 전 확인 창 → 최종 제출 → 완료 화면(제출일시, 제출번호 8자리)
- 필드별 오류 표시, 중복 제출 차단, 저장 실패 시 성공 화면을 띄우지 않음

**관리자 페이지 (PC 표 / 휴대폰 카드형)**
- 집계: 전체 제출 / 의견서 내용 동의 / 의견서 내용 동의하지 않음 (유효 건만)
- 목록: 최신순, 동·호수·성명 검색, 의견·상태 필터, 서명 확대 보기, 접속 IP·브라우저(필요할 때만 펼쳐 보기)
- 무효 처리(삭제 아님, 사유 기록 가능) → 집계 제외, 같은 동·호수 재제출 가능
- CSV 다운로드 (엑셀에서 한글이 깨지지 않도록 UTF-8 BOM 포함)
- **의견서 문구 수정**: 제목·본문·하단 안내·제출처를 고쳐 미리보기 후 게시 → 새 버전(V2, V3…)으로 주민 페이지에 즉시 반영. 버전별 전체 문구·해시·제출 건수 확인, 이전 문구로 되돌리기(새 버전으로 재게시)

## 온라인 동의서 안건 (2026-09-29 개편)

### 안건과 버전

| 구분 | 뜻 | 바뀌면 |
|---|---|---|
| 안건 (`agendas`) | 무엇에 동의받는지 (기록·집계·중복 기준의 단위) | 새 안건은 기록이 따로 시작. 다른 안건에 참여한 세대도 참여 가능 |
| 버전 (`consent_versions`) | 같은 안건의 게시 문구·질문·개인정보 안내 이력 (V1, V2…) | 같은 안건이므로 이미 참여한 동·호수는 다시 참여할 수 없음 |

- 공개 중인 안건은 DB가 1개만 허용합니다(`uq_agenda_public`). 관리자 `안건 목록`에서 공개 전환·접수 중지/재개·새 안건 만들기를 합니다.
- 공개 전환·접수 중지는 기록을 지우거나 바꾸지 않습니다. 기존 안건의 제출을 일괄 무효 처리하는 방식은 쓰지 않습니다.
- 처음 시작할 때(`init_db`) 기존 의견서를 **기존 안건(공개 중)** 으로 등록하고, 새 안건은 **비공개 초안**으로만 만듭니다. 새 안건은 관리자가 게시·공개하기 전에는 주민에게 보이지 않습니다.

### 주민 화면 (공개 전환 후 `/opinion`)

아파트명 · 제목/부제 · 수신/참조 → 취지와 주민 요구사항(①~⑥) → 질문 1~3(각각 `동의합니다`/`동의하지 않습니다` 라디오, 기본 선택 없음)
→ 참여 대상 · 동/호수/성명/서명 · 참여·집계 안내 → 개인정보 수집·이용 안내와 선택 → 제출처별 제3자 제공 안내와 선택 → 최종 확인 체크 → 제출 전 확인 창 → 완료 화면(제출번호, 한국시간).

- 개인정보 수집·이용·국외 이전·제출처별 제공 동의는 항목마다 따로 받고 따로 저장합니다. 화면에는 **'개인정보 관련 항목에 모두 동의합니다'** 체크박스가 있어 한 번에 모두 '동의합니다'를 고를 수 있고(항목별로 바꿀 수 있음), 긴 안내문은 '안내 보기'로 접혀 있습니다(관리자 미리보기에서는 펼쳐짐). 화면 배치만 바뀌므로 게시된 문구·확인값은 그대로입니다.
- 일부 동의·전부 비동의도 접수됩니다. 최종 확인은 "표시한 답변이 본인의 의사"라는 확인이며 모든 요청 찬성이 아닙니다.
- 개인정보 **수집·이용**에 동의하지 않으면 제출할 수 없습니다(문안의 거부 시 영향과 일치). 제출처 **제공**에 동의하지 않아도 제출됩니다(해당 제출처 자료에서만 빠짐).
- 작성 중 새 버전이 게시되면 제출이 저장되지 않고 "새로고침" 안내가 나옵니다. 새로고침하면 동·호수·성명은 유지되고 답변과 서명은 다시 입력합니다.
- 성공 화면은 DB 저장(답변·제공 동의까지 한 트랜잭션) 뒤에만 나옵니다. 페이지마다 임의 토큰을 붙여, 응답이 끊겨 다시 눌러도 두 번째 기록이 생기지 않고 첫 제출번호가 돌아옵니다.

### 개인정보 국외 이전 동의 (2026-09-29 추가)

서버와 DB가 Render 싱가포르 리전에 있어, 개인정보 수집·이용 동의 다음에 **5-1. 개인정보 국외 이전 동의**를 따로 받습니다.
이전 항목·국가·시기와 방법·이전받는 자(Render Services, Inc., privacy@render.com)·이용 목적·보유기간·거부 방법과 효과를 안내하고,
동의해야 온라인으로 제출할 수 있습니다. 동의하지 않는 주민의 **다른 참여 방법**은 운영자가 입력해야 게시할 수 있습니다.
관리자 문구 편집에서 끌 수 있으며, 끄면 대신 '개인정보 저장 위치'를 채워야 합니다. 이 기능 이전에 게시된 버전에는 나타나지 않습니다.
동의 여부는 `consent_submissions.overseas_consent`(nullable)에 저장합니다. 이 칸은 표가 처음 만들어진 뒤에 추가되어,
시작할 때 없는 경우에만 `ALTER TABLE … ADD COLUMN`으로 더합니다(기존 행 값은 비어 있음, 이전 코드는 이 칸을 읽지 않음).
이전 코드로 되돌리면 그 코드는 이 질문을 표시하지 못하므로, **국외 이전 질문이 들어간 버전을 공개한 뒤에는 되돌리기 전에 먼저 접수 중지**를 합니다.

### 저장 구조 (새 테이블, 기존 테이블은 변경 없음)

| 테이블 | 내용 |
|---|---|
| `agendas` | 코드, 이름, 종류(`legacy_opinion`/`consent`), 공개 여부, 접수 여부 |
| `consent_drafts` | 안건별 관리자 초안 (자유롭게 수정) |
| `consent_versions` | 게시 버전 원문 전체(JSON), 버전 이름 `{안건코드}_V{n}`, SHA-256, 해시 방식, 게시 시각·IP. **수정·삭제 없음** |
| `consent_submissions` | 안건·버전·해시, 동·호수·성명, 서명 PNG(bytea), 개인정보 수집·이용 동의, 최종 확인, 제출 토큰·요청 해시, 접속정보 수집 여부와 IP·브라우저, 서버 수신시각(UTC 저장·한국시간 표시), 상태(`ACTIVE`/`INVALIDATED`/`WITHDRAWN`)·처리시각·사유·제출처 전달 후 처리 여부 |
| `consent_answers` | 제출별 질문 고정 식별자(`q1`, `q2`, …)와 답변(`AGREE`/`DISAGREE`) |
| `consent_provisions` | 제출별 제출처(`company`, `district`, 편집 화면에서 추가한 `recipient3`…) 제공 동의, 철회 시각·사유·전달 후 철회 여부 |

- **중복 방지**: `UNIQUE (agenda_id, building, unit) WHERE status = 'ACTIVE'`. 같은 안건에서는 버전이 바뀌어도 동·호수당 유효 1건, 동시에 제출해도 DB가 1건만 받습니다. 무효·철회 처리하면 그 안건 안에서 재제출할 수 있습니다.
- 질문 식별자는 다시 쓰지 않습니다. 질문을 숨기면 비활성으로 남고, 새 질문은 그 안건에서 한 번도 쓰지 않은 번호를 받습니다. 과거 답변은 제출 당시 버전 원문으로 재현됩니다.
- 제출처도 같습니다. 편집 화면의 **새 제출처 추가** 칸(최대 5곳)에 '제공받는 자'를 적어 저장하면 그 안건에서 한 번도 쓰지 않은 식별자(`recipient3`…)를 받고,
  주민 화면에 그 제출처의 제공 동의 질문이 늘어납니다. 추가한 제출처는 지울 수 없고(게시 전에는 '이 문구로 초안 되돌리기'), 추가 전 버전으로 받은 제출은 그 제출처 명단에 들어가지 않습니다.
- 같은 식별자의 질문 문구를 고쳐 게시하면 이전 답변과 합산되므로, 게시 전에 둘 중 하나를 고르게 합니다.
  **새 질문으로 분리**(편집 화면 체크: 고친 문구는 새 식별자, 이전 식별자는 게시됐던 문구로 '사용 안 함') 또는
  **이전 답변과 합산**(오탈자·표현 수정처럼 뜻이 같을 때만, 게시 화면에서 확인란 체크). 선택 없이 게시하면 막힙니다.

### 본문 확인값 (해시 방식 `consent-json-v1`)

게시 버전 원문 전체를 정규화한 JSON(`ensure_ascii=False`, 키 정렬, 공백 없는 구분자, UTF-8)의 SHA-256입니다.
대상: 아파트명·제목·부제·수신·참조·머리 안내, 본문 절 전체, 질문 영역 제목·안내, 모든 질문(식별자·제목·내용·선택지·사용 여부), 참여 대상·입력 안내·참여/집계 안내,
개인정보 수집·이용 안내 전체와 접속정보 수집 설정, 제출처별 제공 안내 전체, 제공·공개 원칙, 최종 확인 문구, 하단 안내.
운영 확인 항목(제출처별 제출 방식, 파기 계획)처럼 주민 화면에 나오지 않는 설정도 게시 버전 JSON에 들어 있어 확인값에 포함됩니다.
게시할 때 정규화(문구 끝 공백·CRLF 정리)한 뒤 저장하고, 확인은 **저장된 JSON 그대로** 다시 계산해 비교합니다(버전별 `hash_scheme`).
나중에 문구 항목이 늘어나도 이미 게시된 버전의 확인값 판정은 바뀌지 않습니다. 기존 의견서의 해시(제목+문단+하단 안내+제출처)는 그대로 두고 다시 계산하지 않습니다.

### 관리자

- `동의서 문구`: 머리글, 본문 절(추가·삭제·순서), 질문(제목·내용·선택지·순서·추가·사용 안 함), 참여 안내·입력 안내, 개인정보 주체·책임자·연락처·목적·항목·기간·저장 위치·거부 안내, 제출처별 제공 내용·기간, 최종 확인·하단 안내를 각각 고칩니다.
  흐름: 편집 → **초안 저장** → **저장된 초안 전체 미리보기**(주민 화면 그대로, 제출 불가) → 확인 결과 → **게시**(새 버전). 서식은 `**굵게**`, 줄바꿈, 빈 줄(문단)만 되고 HTML·스크립트는 글자 그대로 보입니다.
- **게시 차단**: 참여 대상, 개인정보 수집·관리 주체·책임자·연락처·동의자료 보유기간, 국외 이전 동의를 켠 경우 거부 시 다른 참여 방법(끈 경우 저장 위치), (수집 시) 접속정보 보유기간, 제출처별 보유기간,
  운영 확인 항목(제출처별 **제출 방식**, 보유기간 종료 후 **파기 대상·실행 방법·백업 처리** — 주민 화면에는 표시되지 않음)이 비어 있거나 `[게시 전 입력` 표시·짝이 맞지 않는 `**`가 남아 있거나, 접속정보를 수집하지 않도록 했는데 문구에 IP·브라우저 안내가 남아 있으면 게시·공개가 막히고 항목이 표시됩니다.
- `온라인 동의서` 현황: 유효/무효/철회 건수, 질문별 동의·비동의(합산하지 않음), 답변 유형(모두 동의/일부/모두 비동의), 제출처별 제공 동의·비동의·철회와 **질문별 기명 동의자 수**(= 유효 + 그 질문 동의 + 그 제출처 제공 동의·미철회), 버전·상태·질문 답변·제공 동의·동·호수·성명 필터.
  문서 버전 필터를 고르면 집계도 그 버전으로 받은 기록만, 그 버전의 질문 문구로 계산합니다.
- 출력(모두 관리자 로그인 필요, 접속 IP·브라우저 정보 없음):
  - 내부용 CSV(필터 적용), 제출별 **내부 열람용 PDF**(제출 당시 원문+선택 표시, 개인정보·제공 동의 상태, 동·호수·성명·서명, 제출번호·일시·버전·확인값, 상태·사유, 출력일시)
  - 제출처별 **명단 PDF·CSV**와 제출별 **제출처용 PDF**: 유효 + 그 제출처 제공 동의(미철회) + 1개 이상 요청 동의 기록만. 각자의 질문별 실제 답변을 그대로 싣고, 다른 제출처에 대한 선택은 싣지 않습니다.
- **서면용 빈 동의서 PDF** (현황 화면·버전 기록): 게시된 버전 문안 그대로, 답변 체크칸과 동·호수·성명·서명·작성일 빈칸. 서면 제출자는 해외 서버에 저장되지 않으므로 국외 이전 동의 부분은 빼고 '서면 제출 안내'와 운영자가 입력한 '다른 참여 방법'을 넣습니다. 편집 화면에서 초안으로 미리 볼 수 있습니다(초안 표시, 배포용 아님). 서면 제출분은 시스템 집계·제출처 명단에 들어가지 않으므로 따로 세고, 온라인 시스템에 입력하지 않습니다(입력하면 해외 서버에 저장됨). 같은 동·호수가 온라인과 서면에 모두 있는지는 직접 확인합니다.
- 제출별 무효(중복·타인 명의 등)·철회(본인 요청) 처리와 제출처별 제공 동의 철회: 사유 필수, 기록 보존, 집계·제출처 자료에서 제외. "이미 제출처에 전달된 자료" 여부를 함께 기록합니다(이미 전달된 사본은 이 처리로 회수·삭제되지 않으므로 제출처에 따로 알려야 함).

### 개인정보·로그

- 접속 IP·브라우저 정보는 버전 설정(`접속 IP 주소·브라우저 정보 수집`)이 켜져 있을 때만 저장되며, 끄면 안내 문구에서도 빠집니다. 관리자 상세 화면에서만 보이고 PDF·CSV·제출처 자료에는 없습니다.
- 앱 로그에는 제출번호·버전·건수·관리자 로그인 IP만 남고 성명·동호수·답변은 남기지 않습니다(`--no-access-log`, DB 오류 값 숨김, fontTools 로그 차단).
- Render 플랫폼 자체의 요청 기록(접속 IP 등)은 앱 설정과 별개로 Render 정책에 따라 보관됩니다.
- **파기 방법**
  - 접속 IP·브라우저 정보: 관리자 `온라인 동의서` 현황 아래 **접속 IP·브라우저 정보 파기**(제출 후 N일(1일 이상) 지난 기록의 IP·브라우저만 삭제, 남아 있는 건수 표시, 실행 전 확인 창).
  - 동의자료 전체(보유기간 종료 시): 운영자가 결정한 뒤 DB에서 해당 안건 기록을 삭제하거나 DB를 삭제합니다. 앱에는 일괄 삭제 버튼이 없습니다(실수 방지). 필요한 경우 Render 대시보드에서 작업 PC IP를 잠시 허용하고 `psql`로 처리합니다.
  - 백업: Render 유료 DB의 시점 복구 데이터(Hobby 3일·Pro 7일)와 수동 내보내기(생성 후 7일)는 기간이 지나면 Render가 지웁니다. 내려받은 백업 파일은 운영자가 보관기간 뒤 직접 삭제해야 합니다.

## 운영 반영 절차 (승인 후에만)

> 개발 브랜치 `feature/consent-agenda-20260929`. 운영 DB 변경·배포·새 안건 공개는 소유자 승인 뒤에 합니다.
> 저장소가 공개 상태라 브랜치를 올리면 초안 문구도 공개됩니다.

1. **백업**: Render 대시보드 → `ecoforet-opinion-db` → Recovery → **Create export** → 내려받아 안전한 곳에 보관(개인정보 포함). 반영 시각도 적어 둡니다(시점 복구 기준, Hobby 3일 이내).
2. **배포**: main에 반영 후 Render에서 배포(현재 설정: main 커밋 자동 배포 켜짐, 다만 지금까지는 API로 배포됨). 시작할 때 없는 테이블 6개와 인덱스만 만들고 기존 두 테이블은 건드리지 않습니다(`CREATE TABLE`/`CREATE INDEX`만, `ALTER`/`DROP`/`UPDATE` 없음).
3. **확인**: `/healthz`, `/opinion`(아직 기존 의견서), 관리자 `기존 의견서` 건수·CSV·PDF가 이전과 같은지, `안건 목록`에 기존 안건(공개 중)·새 안건(비공개)이 보이는지.
4. **새 안건 준비**: `동의서 문구`에서 게시 전 입력 항목을 채우고 초안 저장 → 전체 미리보기 → 게시(V1). 이 시점에도 주민 화면은 바뀌지 않습니다.
5. **공개**: `안건 목록`에서 새 안건 **주민 페이지에 공개**(필요하면 먼저 `접수 중지` 상태로 공개해 화면만 확인한 뒤 `접수 재개`).

**되돌리기(신규 기록은 지우지 않음)**

- 1단계(권장, 배포 없음): `안건 목록`에서 새 안건 **접수 중지** 또는 기존 안건을 다시 **공개**. 모든 기록 유지.
- 2단계(코드 되돌리기): Render에서 이전 배포(d918ed3)로 Rollback. 새 테이블과 신규 기록은 DB에 그대로 남고 이전 코드는 이를 읽지도 쓰지도 않습니다. 이 경우 `/opinion`은 기존 의견서 화면으로 돌아가 **기존 의견서 접수가 다시 열립니다**(이전 코드에는 접수 중지 기능이 없음). 다시 새 코드로 배포하면 안건·기록이 그대로 이어집니다.
- DB 자체 복구가 필요할 때만 시점 복구(새 DB 인스턴스로 복원)를 쓰며, 그 시각 이후 기록은 새 DB에 없으므로 기존 DB에서 옮겨야 합니다.

로컬 검증(가상 데이터): 이전 코드로 기존 상태(문서 2버전·제출 40건·무효 2건) 생성 → `pg_dump` 백업 → 새 코드 시작 → 기존 두 테이블 전체 값 해시 동일, 기존 CSV·PDF 동일 → 새 안건 게시·공개·제출 6건 → 이전 코드로 롤백해 기존 화면·제출·관리자 정상, 새 테이블 불변 → 새 코드 재배포 후 새 기록 유지 → 백업 복원본이 반영 전 상태와 동일.

## 로컬 실행

1. Python 3.12 (3.13도 동작)로 가상환경을 만들고 의존성을 설치합니다.
   ```bash
   python -m venv .venv
   .venv\Scripts\python -m pip install -r requirements-dev.txt
   ```
2. PostgreSQL에 DB를 만들고 `.env.example`을 `.env`로 복사해 값을 채웁니다 (`DATABASE_URL`, `SECRET_KEY`, `ADMIN_PASSWORD`, `APP_ENV=development`).
3. 실행합니다. 첫 실행 때 테이블과 의견서 첫 버전이 자동으로 만들어집니다 (`python -m app.init_db`로 따로 만들 수도 있음).
   ```bash
   .venv\Scripts\python -m uvicorn app.main:app --reload --port 8000
   ```
4. 브라우저에서 `http://127.0.0.1:8000/` (주민), `http://127.0.0.1:8000/admin` (관리자)

## DB 구조

**opinion_submissions** (제출)

| 컬럼 | 타입 | 설명 |
|---|---|---|
| id | integer PK | 내부 번호 (화면에 노출 안 함) |
| public_id | uuid, unique | 제출번호의 원본 (앞 8자리를 제출번호로 표시) |
| building / unit | varchar | 동 / 호수 (`0101`, `101동`, 전각 숫자도 `101`로 정규화) |
| resident_name | varchar(50) | 성명 |
| opinion_choice | varchar | `AGREE` / `DISAGREE` (CHECK 제약) |
| signature_data | **bytea** | 서명 PNG (흰 배경 흑백, 600×300, 보통 3~8KB) |
| additional_comment | text | 기타 의견 (최대 1,000자) |
| statement_confirmed / usage_consent | boolean | 두 동의 (둘 다 true가 아니면 DB가 거부) |
| document_title / document_version / document_text_hash | varchar | 제출 당시 의견서 제목·버전·본문 SHA-256 |
| ip_address / user_agent | varchar | 접속 IP·브라우저 (보조 자료) |
| submitted_at | timestamptz | 제출 시각 = 서버 수신 시각 (UTC 저장, 화면은 한국시간) |
| created_at | timestamptz | DB 저장 시각 |
| status | varchar | `ACTIVE` / `INVALIDATED` |
| invalidated_at / invalidated_reason | | 무효 처리 시각·사유 |

- **중복 방지**: `UNIQUE (building, unit) WHERE status = 'ACTIVE'` 부분 유니크 인덱스. 같은 동·호수의 유효 제출은 DB에서 1건만 허용하고, 무효 처리된 기록은 남겨 둔 채 재제출을 허용합니다. (단순 `UNIQUE(building, unit)`이면 무효 처리 후 재제출이 불가능해서 이렇게 구성했습니다.)
- 동시에 같은 동·호수로 제출해도 DB 인덱스가 한 건만 받아들입니다.

**opinion_documents** (의견서 버전)

| 컬럼 | 설명 |
|---|---|
| version_no, version | 버전 번호, 이름 (`EPOXY_OPINION_V1`, `…_V2`) |
| title, body, notes, recipient | 제목, 본문(빈 줄로 문단 구분, `**굵게**`), 하단 안내(줄마다 한 항목), 제출처 |
| text_hash | 본문 SHA-256 |
| is_active | 주민 페이지에 게시 중인 버전 (DB가 1개만 허용) |
| created_at, created_ip | 게시 시각, 게시한 관리자 IP |

버전은 수정·삭제되지 않고 새로 쌓이기만 합니다.

## 주민의견서 (기존 안건) 문구 수정과 버전

- 관리자 `의견서 문구` 메뉴에서 수정 → **미리보기** → **게시**. 게시하는 순간 주민 페이지가 새 버전으로 바뀝니다.
- 이미 제출된 의견서는 제출 당시 버전 이름과 해시를 그대로 가지고 있고, 관리자는 버전별 전체 문구를 볼 수 있습니다.
- 게시 순간 작성 중이던 주민이 제출하면 "의견서 내용이 변경되었습니다. 새로고침…" 안내가 나오고 저장되지 않습니다 (옛 문구에 서명한 것으로 기록되지 않도록).
- 수집 도중 문구를 바꾸면 주민마다 서명한 문구가 달라집니다. 가능하면 링크를 배포하기 전에 문구를 확정해 주세요.
- 해시 계산: `제목`, 각 문단(굵게 표시 기호 제외), 각 하단 안내, `제출처: …`를 줄바꿈으로 이어 NFC 정규화한 UTF-8 문자열의 SHA-256. `python -m app.document`로 첫 버전 원문과 해시를 출력할 수 있습니다.
- 첫 버전(V1)은 `주민의견서에코포레.pdf`와 같습니다. 단, 하단 두 번째 안내는 개발 지시서 문구(`…제출될 수 있습니다.`)를 따랐습니다. PDF 문구는 `…제출될 수 있음에 동의합니다.`이며, 온라인에서는 이 동의를 별도 체크박스로 받습니다.

## 서명 저장

- 화면 크기와 상관없이 필기 좌표를 비율로 저장했다가 600×300 흰 배경 PNG로 다시 그려 보내므로, 화면 크기가 달라도 서명이 잘리지 않습니다.
- 서버에서 PNG를 다시 검사하고(형식·크기·실제 필기 여부) 흑백 PNG로 재압축해 PostgreSQL `bytea`에 저장합니다. Render 디스크에는 아무것도 저장하지 않습니다.
- 서명 영역에서는 페이지가 스크롤·확대되지 않습니다 (`touch-action: none` + 터치 이벤트 차단).

## 보안

- SQL은 모두 SQLAlchemy 파라미터 바인딩, 화면 출력은 자동 이스케이프, CSV는 수식 실행 방지 처리
- 관리자: 환경변수 비밀번호, 서명된 세션 쿠키(HttpOnly, SameSite=Lax, 운영에서 Secure), 8시간 후 만료, 같은 IP 10회 실패 시 15분 차단
- CSRF: 관리자 폼은 세션 토큰 + 출처 확인, 주민 제출은 같은 출처의 fetch 요청만 허용
- 보안 헤더: CSP(외부 스크립트 없음), 프레임 삽입 금지, HSTS(운영), 검색엔진 수집 금지(noindex), 위치·카메라 권한 차단
- API 문서(/docs) 비활성화, 디버그 모드 없음, DB 주소·비밀번호 코드에 없음
- 완료 화면 주소는 서버가 서명한 값이라 위조한 "제출 완료" 링크는 열리지 않습니다

## Render 배포

### Blueprint로 배포 (권장)

1. 이 폴더를 GitHub 저장소로 올립니다 (`.env`, `.localdb/`는 `.gitignore`로 제외됨).
2. Render 대시보드 → **New → Blueprint** → 저장소 선택.
3. `render.yaml`대로 웹 서비스 `ecoforet-opinion`과 PostgreSQL `ecoforet-opinion-db`(싱가포르)가 만들어집니다.
   - `DATABASE_URL`: DB와 자동 연결 / `SECRET_KEY`: 자동 생성 / `APP_ENV`: production
   - `ADMIN_PASSWORD`: 적용 화면에서 직접 입력 (12자 이상 권장)
4. 배포가 끝나면 확인합니다.
   - `https://ecoforet-opinion.onrender.com/healthz` → `{"status":"ok"}`
   - `https://ecoforet-opinion.onrender.com/` → 의견서 화면
   - `https://ecoforet-opinion.onrender.com/admin` → 관리자 로그인
   (서비스 이름이 이미 쓰이고 있으면 주소 뒤에 임의 문자가 붙습니다. 대시보드에 표시된 주소를 쓰세요.)

실행 명령 (render.yaml에 포함):
```
uvicorn app.main:app --host 0.0.0.0 --port $PORT --proxy-headers --forwarded-allow-ips="*" --no-access-log
```
빌드 명령: `pip install -r requirements.txt`, 헬스체크: `/healthz`, Python 버전: `.python-version` (3.12)

### 요금제 주의

- **무료 Postgres는 생성 30일 후 만료되고, 14일 뒤 데이터가 삭제됩니다 (백업 없음).** 주민 의견을 보관해야 하므로 유료 플랜(render.yaml의 `0.1c-256mb`)을 권장합니다.
- 무료 웹 서비스는 15분 동안 접속이 없으면 잠들고, 다음 접속 때 약 1분 걸려 깨어납니다. 카톡 링크를 누른 주민이 1분 동안 빈 화면을 볼 수 있어 수집 기간에는 유료(`0.5c-512mb`)를 권장합니다.
- 두 가지 모두 `render.yaml`의 `plan`을 `free`로 바꾸면 무료로 시험 배포할 수 있습니다.

### 데이터 보관

- 관리자 CSV 다운로드로 수시로 사본을 받아 두세요. 서명 이미지는 DB에만 있습니다.
